## ScreenGuide Chrome 扩展 重大升级（智能元素定位）

### 问题
用户反馈扩展虽然能弹出窗口，但引导过程中的画圈位置是**预先写死的固定坐标**，根本不考虑用户当前页面实际情况（浏览器窗口大小、缩放比例、页面状态都不同），导致指引完全对不上号。

### 根本原因
- `guides.js` 步骤使用固定 `x, y` 坐标
- `content.js` 只按坐标画圈，从不分析页面上元素的实际位置
- 任何分辨率、缩放、布局差异都会让坐标失效

### 解决方案：智能元素定位系统
重写三大核心文件：

1. **`guides.js`** — 步骤不再定义固定坐标，改为定义元素搜索关键词：
   ```js
   { text: "点击创建按钮", find: { text: ["创建", "+ 创建"], tag: ["button", "div"] } }
   ```

2. **`content.js`** — 新增 `findElement()` 函数：
   - 遍历 DOM 树，检查每个元素的 `innerText`、`aria-label`、`title`、`placeholder`
   - 多关键词部分匹配，按匹配质量打分排序
   - 优先匹配可见的、可交互的元素（button、cursor:pointer）
   - 找到元素后自动滚动到视野内，用 `getBoundingClientRect()` 获取真实位置
   - 在该位置画红圈 + 高亮框 + 步骤编号 + 文字提示框
   - 找不到时显示 "未能在页面上自动找到该按钮，请手动寻找"

3. **`popup.js`** — 发送 `SHOW_STEP` 消息替代 `DRAW_CIRCLE`，传递 `find` 对象

4. **`background.js`** — 添加 `SHOW_STEP` 到消息路由转发列表，修复 `screen.availWidth` 在 service worker 中不可用的问题

5. **`content.css`** — 补充 `sgTipPop`、`sgBannerSlide` 等动画 keyframes

### 重新加载步骤
1. 打开 `chrome://extensions/`
2. 找到 ScreenGuide Assistant，点击**刷新按钮**重新加载
3. 刷新 Facebook Ads Manager 页面
4. 点击扩展图标测试

## ScreenGuide 内置 AI 分析系统（最终版）

### 问题
1. 截图截到的是扩展窗口自身，而不是背后的 Facebook 页面
2. 用户要求扩展**直接内置 AI**，截图→分析→出指导一站式完成，不要复制来复制去

### 根本原因
- `chrome.tabs.captureVisibleTab(null, ...)` 默认截取当前窗口的活动标签页，但 popup 打开后当前窗口就是扩展自己的窗口
- 之前的设计依赖用户手动复制截图给外部 AI，流程繁琐

### 解决方案：内置 AI Vision 分析

**重写四大核心文件：**

1. **`background.js`** — 彻底重写：
   - 新增 `lastUserTab` 跟踪：通过 `chrome.tabs.onActivated`/`onUpdated` 持续记录用户最后浏览的非扩展页面
   - 点击扩展图标时先记录当前标签页，再打开 popup
   - `CAPTURE_SCREENSHOT` 使用 `lastUserTab.windowId` 参数截取正确的页面
   - 新增 `ANALYZE_SCREENSHOT` 处理：在 service worker 中直接调用 OpenAI Vision API
   - 新增 `SAVE_SETTINGS` / `GET_SETTINGS` 用于存储 API Key

2. **`popup.html`** — 全新界面：
   - 右上角「设置」按钮，展开 API Key / Endpoint / 模型选择面板
   - 默认「AI 截图分析」面板：
     - 目标输入框（告诉 AI 你想做什么）
     - 截图预览区
     - 「截取当前页面」按钮
     - 「AI 分析截图并给出指导」按钮
     - AI 分析结果显示区（支持 markdown 渲染）
     - 「在网页上标注重点位置」按钮
   - 保留「操作指南」和「标注工具」面板

3. **`popup.js`** — 完全重写：
   - 设置加载/保存
   - 截图流程 → 显示预览 → 启用 AI 分析按钮
   - AI 分析：发送 dataUrl + userGoal + API 配置到 background
   - 结果显示：simpleMarkdownToHtml 渲染 AI 回复
   - 一键标注：将 AI 分析传给 content script，提取引号内按钮名称并高亮

4. **`content.js`** — 新增 `HIGHLIGHT_ELEMENT` 处理：
   - 从 AI 分析文本中提取引号内文字、中文引号、关键词
   - 在页面上搜索这些文字对应的元素
   - 找到后画红圈 + 高亮框

### API 配置
- 默认使用 OpenAI API (`https://api.openai.com/v1/chat/completions`)
- 支持自定义 Endpoint（兼容 OpenAI 格式的其他服务）
- 模型可选：gpt-4o-mini / gpt-4o
- API Key 保存在 `chrome.storage.local`，仅本地存储

### 工作流程
1. 用户在 Facebook 页面不知道点哪里
2. 打开 ScreenGuide，在目标框输入「我要更换广告主页身份」
3. 点击「截取当前页面」→ 截到正确的 Facebook 页面
4. 点击「AI 分析截图并给出指导」→ 约 5-15 秒
5. AI 回复显示在下方：描述当前页面 + 下一步该点哪
6. 点击「在网页上标注重点位置」→ 扩展自动在网页上给相关按钮画红圈

## ScreenGuide 截图策略修正：先截图，再弹窗

### 问题
用户反馈截图仍然截到了扩展窗口自身，而不是背后的 Facebook 页面。根本原因是：
- 扩展弹出窗口打开后，它成为了浏览器的「当前窗口」
- `chrome.tabs.captureVisibleTab()` 默认截取当前窗口的可见区域
- 所以弹窗打开后再点击「截图」按钮，截到的是扩展窗口

### 根本原因
`captureVisibleTab` 的行为是截取调用时**当前聚焦窗口**的可见区域。当 popup 窗口打开后，popup 就是当前窗口，截的自然是 popup 自己。

### 解决方案：Capture First 策略
彻底重写 background.js 和 popup.js：

**`background.js` 关键改动：**
1. `chrome.action.onClicked` 处理流程改变：
   - 用户点击图标 → **立即获取当前活动标签页**
   - **立即调用 `captureVisibleTab(targetTab.windowId)`** 截取真实页面
   - 将截图数据存入 `pendingScreenshot`
   - **然后**才打开 popup 窗口
   - popup 窗口一打开，就通过 `GET_SCREENSHOT` 拿到预截好的图

2. 新增 `CAPTURE_FRESH` 消息：
   - 用户点击「重新截取」时，再次截取原始标签页
   - 通过 `pendingScreenshot.tabId` 找到原始页面，在其窗口上重新截图

3. 所有标注指令（`HIGHLIGHT_ELEMENT`、`DRAW_CIRCLE` 等）**固定发送到原始标签页**：
   - 不再 query active tab，直接使用 `pendingScreenshot.tabId`
   - 确保标注总是出现在 Facebook 页面上，而不是扩展窗口

**`popup.js` 关键改动：**
1. 启动时自动调用 `GET_SCREENSHOT` 获取预截图
2. 按钮文字改为「重新截取页面」
3. 占位提示改为「点击扩展图标时已自动截取页面」

**`popup.html` 微调：**
- 状态提示文字适配新流程

### 工作流程（新）
1. 用户在 Facebook 页面，点击扩展图标
2. 扩展**先截取 Facebook 页面**（此时 popup 还没打开，当前窗口就是 Facebook）
3. popup 弹窗打开，**自动显示截图**
4. 用户输入目标 → 点击 AI 分析 → 等结果
5. 点击标注 → 红圈直接画在 Facebook 页面上

### 重新加载步骤
同上。
